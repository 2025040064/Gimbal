# 数字识别模型与数据

本目录保留云台数字 0～9 的模型、数据和相关脚本。仓库内固件、算法验证和比赛任务的完成程度不同，不能把模型可运行等同于整机联调完成。

## 模型

- `实测模型/best_calibrated_50.kmodel`：50 张校准图生成的 K230 模型。此前通过 PC 模拟器验证，WonderMK 上曾加载并运行，从摄像头画面得到过数字 1、5、6 的检测结果。摄像头偶发卡在启动阶段的问题尚未定位。
- `实测模型/best.onnx`、`实测模型/best.pt`：该次转换使用的模型。`best.kmodel` 是此前使用的另一份量化结果。
- `历史训练模型/`：工作区 `runs/digits_v8n/weights` 的历史产物。其 `best.pt` 与 `best.onnx` 的哈希均不同于 `实测模型/` 下同名文件，不可混为一谈。

`best_calibrated_50.kmodel` SHA-256：`685401cc61f196702082736f26982e62b17012affcfe3610421063177ce97071`。

## 数据

- `数据集压缩包/digits_dataset_v2_*.zip`：原训练数据集，分成多个独立 ZIP；把所有 ZIP 解压到**同一个目录**，即可还原其中的 `images/`、`labels/` 和 `digits.yaml`。各 ZIP 不是分卷格式，可分别打开。
- `数据集压缩包/calibration_data_*.zip`：原转换校准图片，解压到同一个目录后可用于转换。
- `数据集压缩包/manifest.json`：各压缩包的文件数、字节数和 SHA-256。压缩包已做 CRC 校验；可再用 SHA-256 验证下载结果。
- `实拍原图/` 和 `原始标注样本/`：原始照片及早期标注样本。`训练记录/` 保存已有训练指标和配置。

数据集包含合成图、增强图和少量实拍图；现有实拍验证样本不足，不能将历史训练指标当成比赛现场准确率。上传快照中的 YAML 和部分脚本保留了本机绝对路径，需要根据实际解压位置修改；原 `val_independent.txt` 在本地快照中未找到，独立验证列表需要重新生成。数据和相关来源可能有重叠，训练与验证时应按场景重新划分。

## 脚本

- `板端与训练脚本/k230_yolo_camera.py`：K230 单板相机识别测试，启用 IDE 预览，不发送电机控制数据。模型路径为 `/sdcard/examples/kmodel/best_calibrated_50.kmodel`，需要先把模型放到板端该路径。
- `转换与电脑测试/to_kmodel.py`：K230 nncase 转换，使用 RGB、NCHW、uint8 和等比例填充校准；可通过 `--samples`、`--dataset`、`--model`、`--output` 指定输入和输出。
- `转换与电脑测试/test_det_kmodel.py`：PC 模拟器测试。其默认绝对路径来自原 Windows 工作区；在其他环境中应使用 `--model`、`--image`、`--output` 显式指定路径。
- `训练工具/` 和 `板端与训练脚本/` 保留原训练与测试脚本；脚本中的本机路径、环境依赖和模型版本应按实际情况核对。竞赛开发分支中的 `k230_yolo_vision.py` 是未完成板端适配的历史方案，不能直接当成已验证的云台跟踪程序。

K230 到 STM32 的协议、实机连线、扫场和闭环电机控制仍需要按项目文档单独验证。
