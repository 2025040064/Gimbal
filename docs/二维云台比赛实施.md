# 二维云台比赛实施

复用已实测的数字 1 坐标和跟随方向。STM32 负责任务、运动和 OLED，K230 负责识别和未叠框录像。任务与 ID 烧录前设置，手动摆到水平朝前后复位启动。

- [x] 两轴相对零位、标定模式与软限位，移除摇杆控制。
- [x] 双向 USART3、任务与目标身份确认、链路故障停机。
- [x] A 巡检、B 锁定、C 移动跟踪、D 同 ID 重捕获。
- [x] K230 本地保存未叠框录像与任务事件的代码。
- [x] 26 项 K230 电脑测试、6 组 STM32 比赛逻辑测试及 Keil 构建。
- [ ] 实板核对双向接线、标定、录像和四项比赛流程。

软件范围为水平 ±60°、俯仰 ±20°。脉冲比例、扫描步距和安全速度须实测。MPU6050 不提供水平轴绝对角度，软件步数与实测角度分别记录。B 的计分细则与中心阈值须裁判确认。

## 上板顺序

1. K230 使用 [K230_数字识别_启动排障V2.py](../K230_数字识别_启动排障V2.py)。把 `COMPETITION_MODE` 改为 `True`，保持 `ENABLE_IDE_PREVIEW=True`，并保存为设备启动脚本。
2. 保持 GPIO50/TX → STM32 PB11/RX。核对两端信号电平后，补接 STM32 PB10/TX → GPIO51/RX，保留共地和分别供电。串口参数为 115200 8N1。
3. 默认 HEX 使用静止测试模式 `T`，整个流程不发电机脉冲。让 ID 1 在画面中心，查看 OLED 的 X/Y 和 `CENTER`，遮挡后查看 X/Y 是否回到 -1。改变 ID 时重新构建。若 OLED 显示 `LINK FAULT`，先检查 K230 是否处于比赛模式、反向接线和 K230 的录像日志。
4. 在 `contest_config.h` 选择 `J`，一次只校准一个轴。把云台手动摆到水平朝前，复位后执行一次低速短移动。默认水平轴先发 100 脉冲，可在正负 200 脉冲内调整。量实际转轴角度，按 `360 × 脉冲数 ÷ 转过的角度` 计算每轴输出轴一整圈的等效脉冲数。测试多次并核对方向。水平正方向对应图像右侧，俯仰正方向对应图像下侧。校准各轴安全速度和扫描步距后填入配置，再设置 `MOTION_CALIBRATED=1`。该值为 0 时，A～D 不启动。
5. 每次赛题测试前配置 `CONTEST_MODE` 和 `CONTEST_TARGET_ID`，重新构建和烧录。启动前手动摆回零位。每次测试开始后，STM32 先发送 STOP 同步，再发送 SCAN 或 ID 指令。K230 回传带模式、目标 ID 和观测序号的坐标帧。六或七字段旧帧只用于显示。

## 计时与验收

| 项目 | 软件记录与实板检查 |
| --- | --- |
| A | 以 60 秒截止时的 OLED ID 清单为准。用随机分布的五张牌检查覆盖、去重和误检。 |
| B | 每个目标从统一零位开始。15 秒内达到连续居中 1 秒后，统计接下来 5 秒的居中毫秒数。中心阈值暂设每轴 ±12 px，最终以裁判口径为准。 |
| C | 前 15 秒允许获取目标，OLED 显示 `MOVE NOW` 后开始本机 15 秒计时。水平和倾斜轨迹各运行一次。本机识别中断只记为提示，是否实际出画和裁判开始时刻以视频复核。 |
| D | 首次锁定后，OLED 的 `WAIT LOSS` 表示可遮挡。识别到目标丢失后暂停，随后搜索同一 ID。软件以检测到丢失后约 2 秒作为重现时间估计，实际重现时刻及 8 秒截止以原始视频复核。 |

K230 在 `/data/gimbal_NNNN` 保存未叠框的 `camera.mjpeg` 和 `events.csv`。每一帧都带相对时间记录，实际采样速度由相机、压缩和存储共同决定。可以用 `ffplay -f mjpeg -framerate 10 camera.mjpeg` 预览，精确计时请用 CSV。板端先检查路径可写、录像可播放、无叠框和帧间距，再做正式测试。可临时关闭 `CONTEST_RECORDING` 来单测链路，正式测试应打开。

Keil 的 LED 目标已构建通过，0 错误、0 警告。产物位于闭环工程的 `MDK-ARM/LED/LED.hex`。默认固件保持静止，当前交付未烧录。CanMV 图像压缩接口参考 [K230 图像处理 API](https://www.kendryte.com/k230_canmv/zh/v1.2/api/openmv/image.html#compressed)，WonderMK 0.4.0 的录制能力仍需实测。
