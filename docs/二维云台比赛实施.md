# 二维云台使用说明（2026-11-15 当前流程）

以用户最新要求为准：移动与遮挡没有固定顺序。当前为一个持续搜索、居中跟踪、丢失等待、重捕获的流程。原固定 ABCD 轮次已取消；旧实施过程保存在工程架构方案和备份中。

## 使用方法

1. 只修改 `8.目标追踪【闭环】/HARDWARE/APP/contest_config.h` 的 `CONTEST_TARGET_ID` 为 0–9，再编译烧录。当前 ID 为 1。内部 `CONTEST_MODE='F'` 是固定的持续流程设置，比赛时不用修改。
2. K230 保持现有 `k230视觉云台.py`，GPIO50/TX 接 STM32 PB11/RX，GND 共地；115200、8N1，无需接 K230 RX。
3. 先运行 K230，确认状态 `link=TX_ALL` 和目标数字检测结果，再把云台摆平、朝前并复位 STM32。自动调平尚未接入，仍以复位位置作为相对零位。
4. 每次复位都重新搜索所设 ID，不读取之前版本的轮次记录，也不会切换到其他项目。

## 实际运行行为

| 情况 | 云台行为 / OLED |
| --- | --- |
| 启动后尚未找到目标 | 扫描寻找指定 ID，显示 SEARCH |
| 找到指定目标 | 立即按像素误差跟踪，显示 TRACK |
| 连续 1 秒处于中心容差内 | 显示 CENTER，仍持续跟踪移动目标 |
| 明确丢失目标 | 立即停止脉冲，保留当前软件位置，不回零；显示 LOST WAIT 和剩余毫秒 |
| 丢失不到 2 秒就找回 | 立即恢复同 ID 跟踪，不等满 2 秒；连续居中重新计时 |
| 从第一帧“无指定目标”起满 2000 ms 仍未找回 | 重新搜索，显示 SEARCH，找到同 ID 后继续跟踪 |
| 移动与遮挡再次发生 | 重复以上行为，每次丢失独立计时，不限次数 |

不在 20 秒、60 秒或三次遮挡后结束；不存在固定 ABCD 轮次、复位推进或断电重新 A 的操作。程序不自动判断裁判当前在测哪个项目，比赛计分由现场计时与录像复核。

“无目标”必须是 K230 持续发来的新观测。串口断线和同一旧帧反复发送不等同于目标遮挡：旧观测超过 350 ms 停止运动，500 ms 未收到有效链路帧或 1100 ms 没有新观测则进入故障停机，排除故障后重新摆零复位。其他 ID 不得替代指定目标。

## 运动范围与当前限制

- 搜索从复位俯仰零位开始横扫，后续俯仰在约 ±10° 内搜索；水平软限位 ±60°，跟踪俯仰软限位 ±20°。均依赖 20000 脉冲/圈与实际方向一致，不能代替绝对位置反馈。
- 等待阶段保持的是停止发脉冲后的电机指令位置。电机是否有足够保持力、是否失步或被外力推动，需要实板确认。
- 跟踪增益当前 2000，保留速度上限、加速度限制、中心启停滞回；跟随延迟和过冲仍须实际整定。
- MPU6050 安装方向、PB6/PB7 接线已由用户说明，但自动调平未完成。本次只纠正持续跟踪流程，没有修改识别算法或新增惯性闭环。
- K230 整段录像方式保持原样；单向通信无法由 STM32 下发任务状态，需结合 OLED、STM32 日志和视频复核。
