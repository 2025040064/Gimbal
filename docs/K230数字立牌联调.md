# K230 数字立牌联调

本次实现 B 题的 K230 视觉部分。题目使用数字 0–9，用户确认立牌为白底黑字。K230 负责识别画面内的多个 ID、记录巡检发现的 ID，并在收到指定 ID 后持续输出该牌的中心坐标。云台的统一零位、实际角度、扫场及居中计时由控制端负责。

## 实现安排

1. 在原 `k230视觉云台.py` 中保留 640×480 采集，使用 CanMV IDE 虚拟显示。用白底区域找立牌，在牌内提取黑色数字。数字匹配用内置的印刷字体模板，拒绝分数接近的结果。
2. 连续看到同一 ID 后确认。巡检模式在收到 `SCAN` 后去重记录，60 秒时输出清单。收到 `ID,n` 后选择该 ID。它离开画面或被挡时发送无目标，出现后重新确认。
3. 坐标仍发 `AA 55`、六个逗号分隔的十进制数和 `0D 0A`。串口收指令和 IDE 查看巡检结果分别验证。画框随相机刷新，坐标发送单独限速。
4. 先在电脑检查识别、命令分包、ID 为 0、干扰目标、遮挡和串口兼容，再用正式立牌与实板测距离、光照和速度。

## 运行与接线

1. 在 CanMV IDE 中打开 `k230视觉云台.py`，连接 K230 后运行。右上角是 640×480 虚拟预览。先确认数字正立，若方向不对，再按相机安装方向调整 `VFLIP` 和 `HMIRROR`。
2. UART2 使用 115200、8N1。庐山派 40Pin 排针的 GPIO5（第 11 脚，TX）接 STM32 PB11（USART3 RX），两板共地。要由 STM32 发送指令，再把 PB10（USART3 TX）接 GPIO6（第 13 脚，RX）。若使用庐山派板载 UART2 四针座，脚本中的 `UART2_TX_PIN` 和 `UART2_RX_PIN` 分别改成 11 和 12。
3. 只测一张指定牌时，可以将 `INITIAL_TARGET_ID` 设为 0–9 中的一个数字并重新运行。默认值 `None` 进入预览，直到 UART2 收到选牌指令才输出有效坐标。
4. 在非白背景上摆两张白底黑字、单个印刷数字的立牌。连续三帧确认后显示数字和框，指定牌用绿色，其余用黄色。测试遮挡和放大干扰牌时，观察 IDE 的 `TRACK,n`、`LOST,n` 以及 STM32 收到的坐标。

### UART2 收指令

每条命令以 LF 或 CRLF 结束。用 USB 转串口联调时，将串口工具的 TX 接 K230 UART2 RX，并共地。

| 指令 | 处理 |
| --- | --- |
| `SCAN` | 开始 60 秒视觉巡检。IDE 逐条打印 `FOUND,n`，到时打印去重后的 `SCAN_RESULT,n1,n2,...`。 |
| `ID,3` | 选择 3 号。其他 ID 即使更大，也不参与坐标输出。 |
| `STOP` | 结束当前巡检或跟踪，回到预览。 |

K230 发给 STM32 的坐标帧仍是 `AA 55 + 图像宽,图像高,中心x,中心y,立牌宽,立牌高 + 0D 0A`。无目标发送 `640,480,-1,-1,-1,-1`。丢失时保留指定 ID，重新出现并连续确认后再输出坐标。坐标发送间隔至少为 50 ms，实际频率取决于采集与处理速度。

## 验证记录

- 电脑端运行 `python -X utf8 -B -m unittest discover -s tests -p test_k230_gimbal.py -v`，8 项通过。覆盖 ID 0、分包、超长指令、巡检去重和截止、干扰牌、遮挡重捕获、旧坐标帧和逐帧预览。
- 合成字形覆盖 9 种字体、4 种字号及 5 个角度。1,800 个样本中 1,655 个识别正确，145 个被拒识，接受的样本未发生错分。4 组模拟画面共 20 块单数字立牌均检出，空白和双数字干扰牌未被选中。图像连通区域由电脑端模拟。
- 原版直接在电脑导入时缺少 CanMV `media` 模块。改用模拟模块并开启 UTF-8 后，复现原版三帧预览均无框。新版的模拟入口验证了绘图与 UART 发送各自运行。
- 初次 Git 检查受目录所有权限制，使用命令级 `safe.directory` 复核。原脚本采用 CRLF，使用命令级 `core.whitespace=cr-at-eol` 后差异检查通过。固件源码树的直接请求返回认证错误，接口用厂商文档核对。

目前可联调 K230 的立牌识别、视觉巡检和指定 ID 坐标输出。正式字体、实物角度、照明、端到端时延和串口接线需要实板验证。整机还需接入统一零位、扫场、居中计时、丢失后的转台搜索以及原始录像。
