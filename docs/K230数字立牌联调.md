# K230 数字立牌联调

## 下载与接线

1. 在 CanMV IDE 打开仓库根目录的 `k230视觉云台.py`。运行前把 `INITIAL_TARGET_ID` 改成所需的整数 `0`～`9`，本版初始值为 `3`。每次换数字都重新下载并运行脚本。
2. STM32 使用 `8.目标追踪【闭环】/MDK-ARM/LED.uvprojx` 重新编译和下载。K230 UART2 的 TX（GPIO5）接 STM32 USART3 的 RX（PB11）并共地，按实物板卡确认针脚和电平。当前链路只需传输 K230 发出的坐标，K230 的 RX（GPIO6）保持配置。
3. 预览为 640×480，`VFLIP` 与 `HMIRROR` 均为 `True`。使用白底黑字的单数字立牌，观察白色画面中心十字和绿色字形中心十字。首次转动时把牌放在中心旁，每次只测一个轴，确认对应误差随云台转动减小。X 轴为电机 2，Y 轴为电机 1。方向配置沿用原工程，可在 `stabilizer.c` 的 `TRACK_X_POSITIVE_DIR` 和 `TRACK_Y_POSITIVE_DIR` 按实测调整。

## 跟踪与收帧

- `detect_cards()` 保留白卡框和黑色字形框，沿用原模板。跟踪前后都全画面检测。`VisionSession.observe()` 只接受指定数字，相互重叠的重复框合并为同一候选，分开的同号候选暂不采用。首次和长遮挡后连续 3 帧确认。锁定后，位置连续的有效检测可立即更新。
- `HOLD` 从上一帧有效检测起计时，满 300 ms 前暂停串口坐标发送。短时恢复后继续跟随，长丢失后发送无目标帧并继续全画面搜索同一个数字。旧 `SCAN`、`ID,n`、`STOP` 指令对固定目标无影响。
- `coordinate_frame()` 的帧结构为 `AA 55` + ASCII `640,480,x,y,w,h` + `0D 0A`。X/Y 为字形中心，W/H 为卡片宽高。无目标时负载为 `640,480,-1,-1,-1,-1`。UART 为 115200 8N1。正常坐标帧发送至少间隔 50 ms，实际帧率取决于识别和显示耗时。
- STM32 的 `K230_Process()` 校验六个字段和坐标范围。`Stabilizer_Update()` 仅随新坐标更新电机控制，水平和俯仰分别以 `(320,240)` 为中心，±12 像素以内停止该轴。收到无目标帧或最新坐标已满 150 ms 时，TIM2 停止输出步进脉冲，电机继续使能。有效帧间隔超过 150 ms 时可能出现间歇停步，上机记录帧间隔后再评估该初值。

## 验证

在仓库根目录运行 `python3 -B -m unittest discover -s tests -v`。10 项测试覆盖配置校验、连续确认、短丢失、跨画面重捕获、重复候选、字形中心、串口发送、计数器回绕和旧指令。闭环 STM32 工程已用 ARM GCC 编译链接，并用模拟 UART 和 TIM2 检查帧解析、死区、停脉冲及恢复。

以下为实机验收记录项，均待实测。遮挡测试可以拍摄同时包含立牌和预览画面的录像，便于在同一时间基准下读数。

| 方案编号 | 操作和观察 |
| --- | --- |
| T01、T02 | 选择 3。先放 3，观察连续 3 帧后进入 `TRACKING`。再只放 1、2、5，确认串口无有效坐标。 |
| T03、T09 | 缓慢横向和纵向移动 3，确认云台减小对应误差。近中心轻微移动，确认两轴在各自 ±12 像素内停止发脉冲。 |
| T04 | 短挡 100～200 ms。若采集到丢失帧，预览显示 `HOLD`，串口不复发旧坐标，恢复后检查下一条有效坐标。 |
| T05、T06 | 遮挡 3～5 秒，把 3 移到画面另一侧并加入 1、5、8。检查遮挡期间停止发脉冲，恢复时只跟随 3。 |
| T07 | 移走目标至少 30 秒。检查识别循环继续运行，无搜索超时报告。 |
| T08 | 从目标首次清晰可见到预览显示 `TRACKING`（也可结合 `TRACK,3,<设备毫秒>`）测量恢复延时，记录是否 ≤2 秒。 |
| T10、T11 | 改为 7 并重启，同时摆放 3 和 7。注入旧串口指令，检查有效坐标仍属于 7。 |
| T12 | 观察 `STATS,<窗口毫秒>,<处理帧数>,<有效坐标帧数>`，分别用计数除以窗口秒数得到实际识别帧率和有效坐标频率。 |

## WonderMK I2C 历史记录

本方案使用 UART。若实物是旧联调资料里的 WonderMK，先确认板卡是否能引出所需 UART2 引脚。以下是此前对 I2C 接口的核对。

用户提供的 WonderMK 基础课程 `源码/IIC.py` 配置 GPIO11 为 I2C2 SCL、GPIO12 为 I2C2 SDA，采用 `I2C_Slave` 和 7 位地址 `0x10`。该示例需要实际运行检查 `I2C_Slave.list()` 是否包含可用设备。

同套资料的原理图第 4 页中，I2C 接口 J4 的 1 脚为 SCL、2 脚为 SDA、3 脚为 GND、4 脚为 5V。模块可继续通过 Type-C 供电，只连接信号与共地时不要再接 J4 的 5V。以实物板卡与原理图对应为前提核对针脚。

STM32 闭环工程使用 PB6/SCL、PB7/SDA 通过软件 I2C 连接地址为 `0x68` 的 MPU6050。WonderMK 与 MPU6050 地址不同，可以研究共用该总线。当前软件 I2C 没有检查 SCL 时钟拉伸，且 K230 接收程序仍是 USART3，直接接线后无法完成通信。需要修改和测试两端软件，再验证电平、总线时序和实物通信。
