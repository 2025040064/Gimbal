# 云台数字目标追踪 —— 系统架构与部署方案

> 竞赛题：STM32 云台 + K230 视觉下位机，识别白底黑字 0-9 数字牌（ID），完成巡检 / 指定锁定 / 移动跟踪 / 遮挡重捕获。
> 本文件为整套方案的权威说明，覆盖模型链路、串口协议、K230 推理脚本、STM32 对接边界、部署清单与测试计划。
>
> **硬约束**：绝不修改任何 STM32 的 `.c/.h` 源码。所有模型/训练/脚本产出在 `训练数字\`，文档即本 `架构方案.md`。

---

## 1. 系统总览

```
┌──────────────┐   UART3 (115200 8N1)   ┌──────────────────┐
│  K230 (视觉)  │ ── 检测帧 ───────────▶ │   STM32 (控制)   │
│  YOLOv8n KPU  │ ◀── 控制命令 ───────── │  云台 + 状态机    │
└──────────────┘                        └──────────────────┘
   640×480 取流                               A/B/C/D/J/T 状态机
   resize 320×320 推理                            (已闭环，不改动)
   class index == digit ID
```

- **K230 职责**：摄像头取流 → YOLOv8n INT8 推理 → 解析框与类别（类别号即数字 ID）→ 按协议打包发给 STM32。
- **STM32 职责**：解析帧、运行云台运动学状态机（A/B/C/D/J/T），并下发 `SCAN / ID,n / STOP` 控制命令。
- **识别在哪里做**：全部在 K230 上。STM32 不解析像素，只认"哪个 ID、在画面哪个位置"。

## 2. 模型链路（PC 侧已闭环 ✅）

| 阶段 | 产物 | 说明 |
|------|------|------|
| 训练 | `训练数字/runs/digits_v8n/weights/best.pt` (12.3 MB) | YOLOv8n，10 类 0-9，**类别 index == 数字 ID**；输入 320×320；best 指标 mAP@0.5=0.995 / mAP@0.5-95=0.985 / P=0.999 / R=1.0（训练 76/120 epoch 时保存，指标已收敛） |
| 真实验证 | `训练数字/tools/validate_real.py` | 25 张实拍图 **25/25 = 100%** top-1 准确率（置信度 0.80–0.98） |
| 导出 ONNX | `训练数字/runs/digits_v8n/weights/best.onnx` (12.1 MB) | 输入 `[1,3,320,320]`，输出 `[1,14,2100]`（4 框 + 10 类）；opset=12，无动态维度、无 NMS、无 half |
| 转 kmodel | `训练数字/runs/digits_v8n/weights/best.kmodel` (3.34 MB) | **nncase 2.9.0 INT8**，target `k230`，magic `LDMK` |
| K230 脚本 | `STM32代码/k230_yolo_vision.py` | 复用原 `k230视觉云台.py` 的 sensor/UART/协议/状态机，仅把检测核心换成 YOLO |

> **输入尺寸决策**：sensor 取流 640×480 与模型输入 320×320 是两回事。推理时 resize/letterbox 喂入 320；320 下 KPU ~30 FPS，640 仅 10–15 FPS。数字牌白底黑字、对比度高、目标 ~50px 远超 8px 检测门槛，320 已 100% 验证可用。

### 数据集
- `训练数字/digits_dataset_v2/`：合成 6000 + 25 张实拍变体，train 5495 / val 625，10 类均匀、零标注错误。
- `训练数字/tools/`：`synthesize_digits.py`（白底黑字印刷体合成）、`build_dataset_v2.py`、`label_digits.py`、`test_pretrained_onnx.py`、`to_kmodel.py`（nncase 转换脚本）。
- 现成权重（thawro ONNX / SVHN .pt）域不匹配，实拍实测仅 64%，已弃用。

## 3. 串口协议（K230 ↔ STM32）

**K230 → STM32**（由 `coordinate_frame()` 生成，STM32 侧 `HARDWARE/K230/k230.c` 的 `K230_Parse` 解析）：

```
b"\xAA\x55" + "width,height,x,y,box_w,box_h,ids,mode,id,sequence" + b"\r\n"
```
- `width,height`：帧分辨率（640,480）。
- `x,y`：选中框中心（TRACK 模式为锁定目标中心，否则 -1）。
- `box_w,box_h`：选中框尺寸（-1 若无）。
- `ids`：bitmask，第 d 位 = 数字 d 被检出。
- `mode`：0=IDLE 1=SCAN 2=TRACK 3=FAULT 4=LEGACY。
- `id`：当前锁定目标 ID（-1 若无）。
- `sequence`：自增帧序号（0–65535 循环）。

**STM32 → K230**（200 ms 重发，由 `CommandReader` 解析）：
- `SCAN\n`：进入巡检，累计见到的所有 ID。
- `ID,n\n`（n=0–9）：进入锁定追踪指定数字 n。
- `STOP\n`：停止，回到 IDLE。

## 4. K230 推理脚本设计（`k230_yolo_vision.py`）

**不改动**原 `k230视觉云台.py` 与任何 STM32 源码，新建独立文件。结构上分两块：

1. **复用部分（不动）**：`open_uart()`（GPIO50/51，UART3 @115200）、`CommandReader` / `UARTCommandInput`（命令解析）、`VisionSession`（SCAN/TRACK/IDLE/FAULT 状态机，含连续帧确认 `CONFIRM_FRAMES=3`）、`coordinate_frame()` / `send_coordinates()`（帧格式）、`draw_overlay()`、`main()` 主循环。这些已在原脚本经硬件验证。

2. **唯一替换部分 —— `YoloDetector`**：
   ```python
   class YoloDetector:
       def __init__(self, model_path):
           from libs.YOLO import YOLO          # 固件相关适配点
           self.yolo = YOLO(model_path=model_path, labels=LABELS,
                            model_type=MODEL_TYPE, input_size=INPUT_SIZE,
                            confidence_threshold=CONF_THRESHOLD,
                            nms_threshold=NMS_THRESHOLD)
       def detect(self, img):
           raw = self.yolo.run(img)            # 返回 [(x,y,w,h,class,score), ...]
           return [(int(r[4]), (int(r[0]),int(r[1]),int(r[2]),int(r[3])))
                   for r in raw if 0 <= int(r[4]) < len(LABELS)]
   ```
   关键配置：`DETECT_WIDTH/HEIGHT=640`、`MODEL_PATH="/sd/best.kmodel"`、`INPUT_SIZE=[320,320]`、`CONF_THRESHOLD=0.35`、`NMS_THRESHOLD=0.45`、`LABELS=["0".."9"]`。

> **⚠️ 固件适配点**：`libs.YOLO` 的 import 路径与构造签名随 CanMV 固件版本不同而异。若烧录固件里 `YOLO` 接口不一致，只需改 `YoloDetector` 一处即可，其余协议/状态机代码无需动。

- [ ] 串口接线：K230 GPIO50(TX)→STM32 PB11，GPIO51(RX)→STM32 PB10，115200 8N1。

### ✅ 已完成（PC 侧）
- 模型训练与收敛（mAP@0.5=0.995）。
- 真实场景 25/25 = 100% top-1 准确率。
- ONNX 导出、kmodel 转换（INT8，3.34 MB）。

### ⏳ 待上板验证（需物理 K230 + STM32）
1. **固件确认**：核对 CanMV 固件 nncase = 2.9.0；验证 `libs.YOLO` API 签名与 `YoloDetector` 一致（不一致则改该类）。
2. **单板自检**：K230 加载 kmodel、取流推理、IDE 预览框正确、帧率达标（目标 ~30 FPS @320）。
3. **链路联调**：跑通 A/B/C/D 四模式 ——
   - A：上电自检、建链。
   - B：SCAN 巡检，K230 回报全部可见 ID。
   - C：ID,n 锁定，TRACK 模式持续回报中心坐标。
   - D：遮挡/丢失重捕获（FAULT→重新 SCAN）。
4. **可选**：resume 训练补满 120 epoch（边际收益极小，mAP 已 0.995）。

## 7. 环境配方（可复现）

### kmodel 转换环境（已打通 ✅）
**致命坑：nncase 的 .NET 内核无法读中文路径**，venv 必须建在**纯英文路径**：`F:/A_LIU_Astrspire/A_competition/Gimbal/kmodel_venv/`。

- Python 3.9（`uv python install 3.9` → `uv venv --python 3.9`）；用户硬约束：Python 不得高于 3.9。
- 依赖：`nncase==2.9.0`、`nncase_kpu==2.9.0`(手动解包到 site-packages)、`numpy==1.26.4`、`onnx`、`Pillow`。
- **`libomp140.x86_64.dll`**：pypi 不带，从 conda-forge `llvm-openmp-14.0.6` 取 `Library/bin/libomp.dll` 改名复制进 site-packages（同物异名，Intel OpenMP 运行时）。
- 运行前：`export NNCASE_PLUGIN_PATH=.../site-packages/nncase/modules/kpu`。
- 转换：`to_kmodel.py --model best.onnx --dataset <校准图> --size 320 --samples 100 --target k230`（校准图/ONNX 也需英文路径）。
