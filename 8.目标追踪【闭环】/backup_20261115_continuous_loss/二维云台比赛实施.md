# 二维云台比赛实施

## 固定 ABCD 顺序版（最新使用方式）

比赛只改 `HARDWARE/APP/contest_config.h` 中 `CONTEST_TARGET_ID`（0–9），内部 `CONTEST_MODE='S'` 保持不动，无须选项目。K230 继续使用单向 TX 脚本。

顺序为 A → B1 → B2 → B3 → C-H（水平）→ C-D（倾斜）→ D（三次遮挡在这一轮内进行）→ END。
每轮 DONE 或 TIMEOUT 后停机并保存下一轮；下一次复位或更换 ID 烧录后的启动开始下一轮。中途复位、通信故障后复位重试当前轮。每轮开始前先摆好前向和水平；MPU 自动调平仍未实现。

比赛全程保持 STM32 供电；本程序检测到上电复位就重新从 A 开始，轮次记录丢失/无效也从 A 开始。用正常复位键切换，不能用断电代替。修改 ID 并下载后看 OLED 是否为预期 B1/B2/B3/C-H/C-D/D；实际烧录器可能重置备份域，需要在赛前验证，不能直接保证下载后轮次一定保留。全部完成后 END 保持停机，重新上电可重开整场。

现固件 `8.目标追踪【闭环】/MDK-ARM/LED/LED.hex` 已使用顺序配置编译，0 errors / 0 warnings；主机 15 组通过。没有实板测试。下文 B/F 默认、尚未实现顺序等叙述为历史记录，由本节替代。

## 当前比赛约束（优先于下文）

比赛只修改目标 ID，只有复位键。当前临时恢复 B 模式、ID 1；A–D 按固定顺序自动切换尚未实现，具体顺序和更换 ID 后的烧录、复位规则待确认。现有固件不能声称仅修改 ID 即可完成 A–D 全流程。自动调平未实现；搜索范围及跟踪响应改动见下文。

## 2026-11-15 持续跟踪与搜索幅度调整（部分为历史配置）

默认 `CONTEST_MODE='F'`、目标 ID 1，K230 保持单向 TX 配置。F 持续跟踪，通信故障停机，丢目标后搜索，不按 B 的 20 秒截止。B 保留比赛计时；通过修改 `contest_config.h` 并重新编译选择 B。M 是只读 MPU 检查，J 是单轴点动，T 是静态串口检查，无需日常切换。

B/C/D/F 搜索从复位时的俯仰零位开始横扫，再按零位 -10°、+10° 搜索；A 仍使用完整巡检范围。角度依据复位时位置和步数估算，装配与比例未经本次实测；找不到目标时仍会自动转动，扫描范围覆盖须现场检查。目标丢失后会先短暂停住再搜索。跟踪增益由 1200 提至 2000 以尝试减小延迟，限速及加速度限制保留，实机需观察反向、过冲或振荡。

MPU 自动调平仍未接入。只读固件 `8.目标追踪【闭环】/MDK-ARM/imu-diagnostic-20261115-build/MPU-readonly.hex` 显示 AX/AY/AZ：水平静止、相机轻微上仰、下俯各读一组，用于确认重力轴与机械安装偏差；其 M 模式不会下发电机运动。F 固件 `8.目标追踪【闭环】/MDK-ARM/LED/LED.hex` 启动前仍须人工摆平、朝前再复位。两轴和板上 MPU 尚未实测，不能把主机测试当成调平或跟踪验收。

## 2026-11-15 单向 TX 版（当前有效）

用户只能接 K230 TX 与共地。以下为当前使用方法；后面的双向握手、接 RX、按命令分段录像等内容仅保留为历史记录。

1. 接线只需 **K230 GPIO50/TX → STM32 PB11/USART3_RX**、**GND → GND**。双方串口参数 115200、8N1。无需接 K230 GPIO51/RX。
2. K230 更新并运行 `STM32代码/k230视觉云台.py`，启动标识 `WONDERMK_CONTEST_TX_V6`。默认 `ONE_WAY=True`、`COMMAND_INPUT="none"`。等待 `FIRST_DETECTION`，随后状态应含 `link=TX_ALL`；出现数字 1 时 `cards` 应包含 1。不再等待 `[RX] STOP` 或 `[RX] ID,1`。
3. STM32 烧录本次 `8.目标追踪【闭环】/MDK-ARM/LED/LED.hex`。必须同时更新两端，旧固件不识别新的 ALL 广播帧。
4. 当前 `HARDWARE/APP/contest_config.h` 为 `CONTEST_MODE='B'`、`CONTEST_TARGET_ID=1`、`VISION_ONE_WAY=1`。更换目标仍只修改 STM32 的 `CONTEST_TARGET_ID` 为 0–9，然后编译烧录；K230 不用改目标。
5. 每轮把云台摆回水平朝前零位，再复位 STM32。接收到正常广播后自动开始：未发现指定 ID 时搜索，连续三帧确认该数字后回传有效坐标并跟踪。画面中其他数字也会显示，但不会替代指定目标。B 项整轮 20 秒，结束后停机；下一轮重新摆零复位。

如仍显示 `SYNC TIMEOUT`：先确认新脚本启动标识，再检查 K230 的 TX 确实连到 **PB11**，并确认已烧录本次 HEX。
若 `cards=[]` 持续为空，表示没有已确认的检测结果；这是识别侧证据，不能仅靠改 STM32 ID 解决。目标有效时 OLED 的 X/Y 应不再是 -1；HOLD 需连续居中 1 秒后才开始累计。

录像现为 K230 模型、相机、存储就绪后自动开始，脚本停止时结束，保存到 `/sdcard/gimbal_records/gimbal_NNNNN/` 下的 `camera.mjpeg` 和 `events.csv`。单向通信下 K230 不知道 STM32 的目标与轮次；DETECTION 事件记录序号、ID、框左上角 x/y、宽高，FRAME 时间用于视频复核。不同 STM32 测试轮次可能在同一段录像里，需现场记录复位时间。原始视频与实板写盘性能仍须验收。

验证：STM32 主机 11 组场景、K230 31 项测试通过。Keil LED 目标 0 errors / 0 warnings；构建记录 `8.目标追踪【闭环】/MDK-ARM/oneway-20261115-build/LED-LED-build.log`，HEX/AXF 于 2026-11-15 17:10 更新。未烧录、未实板验证，不能据此认定稳定跟踪或比赛成绩达标。

## 2026-11-15 完整比赛流程版（历史双向方案）

本节替代下文旧版本关于 B 提前结束、无录像、启动标识 V3/V4 的说明。

### 使用步骤

1. 在闭环工程 `HARDWARE/APP/contest_config.h` 修改 `CONTEST_MODE`（A/B/C/D）和 `CONTEST_TARGET_ID`（0–9），编译烧录。当前构建为 **B / ID 1**。
2. K230 使用 `STM32代码/k230视觉云台.py`，模型仍为 `/sdcard/examples/kmodel/best_calibrated_50.kmodel`。保持 IDE 预览开启，双向串口 GPIO50→PB11、PB10→GPIO51、共地、115200 8N1。
3. 等待 `WONDERMK_CONTEST_V5`、`MODEL_LOADED`、`RECORD_READY`、`FIRST_DETECTION`。确保 SD 卡可写且空闲至少 16 MiB。
4. 每轮手动将云台摆到统一水平朝前零位，按 STM32 复位；随后自动握手、发送任务/目标、开始计时和运动。没有运行时选 ID 菜单，复位不提供绝对回零。
5. DONE/TIMEOUT 后电机停止，STM32 重发 STOP，K230 关闭本轮录像。更换模式或 ID 后重新编译烧录，下一轮再次摆零复位。

### 计时与结果

- A：完整扫描 60 s，OLED 显示去重 ID；即使已见 5 个也不提前结束。
- B：前 15 s 连续居中 1 s，随后固定 5 s 保持统计，跟踪至整轮 20 s；未及时锁定显示 LOCK FAILED，20 s 后 TIMEOUT。保持统计不会因后续继续跟踪超过 5000 ms。
- C：READY 倒计时 15 s，再显示 MOVE NOW 并计分 15 s；预锁定失败仍继续搜索。水平和倾斜各测一轮。
- D：锁定后 WAIT LOSS，丢失后固定估计 2 s 遮挡，随后 8 s 重捕获窗口，连续居中 1 s 才成功；共三次，失败后重新锁定才等待下次遮挡。日志 RECAPTURE_EST 明确是估计时间，实际移除时刻必须看原始视频，不以首次识别到目标重新计时。
- 显示 VISION/RECORD 表示 K230 故障；WRONG ID、LINK LOST、STALE VISION、UART TX、CONTROL STALL 分别表示身份不一致、链路断开、观测停滞、发送失败、前台控制超过 100 ms 未更新。

### 录像与复核

目录 `/sdcard/gimbal_records/gimbal_NNNNN/`，每轮包含 `camera.mjpeg` 和 `events.csv`，不覆盖已有目录。新任务开始录像，重复同 ID 不重开，STOP 正常结束；故障/中断保存 END 原因。没有正常 END 的片段不能视为完整录像。
原始画面在叠框前编码，目标帧率 10 fps、JPEG quality 50；事件时间是本轮开始后的真实毫秒数，考虑实际推理/存储性能，不能保证实板达到 10 fps。

事件格式：`elapsed_ms,event,values...`。FRAME 后为 `frame_number,jpeg_bytes,frame_gap_ms,encode_ms,write_ms`；OBS 后为 `sequence,target_id,cx,cy,box_w,box_h`；TIMING 后为 `capture_inference_ms,observation_gap_ms`；COMMAND、TRACK、LOST、START、END 记录操作和身份。RECORD_STATUS 中 total_ms 包含该次编码、事件写入及可能的 flush。
MJPEG 裸流不内嵌可变帧率时间戳：播放器默认速度不能用于比赛计时，必须按 events.csv 的 FRAME 时间复核。首次使用需在实板检查 `frame.compressed(quality=50)` 输出可读 JPEG 缓冲区；接口依据 [CanMV Image API](https://www.kendryte.com/k230_canmv/en/main/api/openmv/image.html)。
低空间、短写或编码异常会报错并向 STM32 发 FAULT，不能静默继续宣称录像成功。两秒收不到 STM32 有效指令会退出并关闭记录。

## 上板顺序

1. K230 使用 [k230视觉云台.py](../k230视觉云台.py)，启动标识为 `WONDERMK_LINK_V3`。保持 640×480、`ENABLE_IDE_PREVIEW=True` 和 `COMMAND_INPUT="uart3"`，运行后检查预览及 `[STATUS]`。
2. 保持 GPIO50/TX → STM32 PB11/RX。核对两端信号电平后，补接 STM32 PB10/TX → GPIO51/RX，保留共地和分别供电。串口参数为 115200 8N1。
3. 当前 HEX 为电机 B 项固件。先将云台摆到水平朝前；K230 运行后复位 STM32，检查 K230 打印 `[RX] STOP`、`[RX] ID,1`。先将 1 号卡放在画面中心附近，再小幅左右、上下移动，检查云台使目标回到中心；反向追离目标时停止运行，再调整对应轴的 `*_POSITIVE_CW`。B 项获取目标限时 15 秒，连续居中 1 秒后进入 5 秒保持统计，完成显示 `DONE`，重新复位开始下一次。若显示 `LINK FAULT`，检查双向接线及 K230 状态输出。
4. 两轴当前均使用已确认的 20000 脉冲/圈，`MOTION_CALIBRATED=1`。更换电机、细分或传动后须重新确认比例与方向。需要单轴测量时在 `contest_config.h` 选择 `J`：默认水平轴低速发 100 脉冲，对应直连轴 1.8°；修改后重新编译烧录。水平正方向对应图像右侧，俯仰正方向对应图像下侧。
5. 每次赛题测试前配置 `CONTEST_MODE` 和 `CONTEST_TARGET_ID`，重新构建和烧录。启动前手动摆回零位。每次测试开始后，STM32 先发送 STOP 同步，再发送 SCAN 或 ID 指令。K230 回传带模式、目标 ID 和观测序号的坐标帧。六或七字段旧帧只用于显示。
